# مشخصات نیازمندی‌ها (خلاصه) و داستان‌های کاربری — فاز ۱

## ۱. دامنه سامانه در فاز ۱

**در دامنه.** ثبت شناسنامه فنی موجودی مازاد پارچه، داوری آگهی، جستجو و فیلتر
چندمعیاره، ثبت درخواست خرید، پیشنهاد قیمت فروشنده، ایجاد سفارش با رزرو موجودی،
پرداخت شبیه‌سازی‌شده، دفتر تراکنش موجودی و ابزار ثبت مصاحبه اعتبارسنجی.

**خارج از دامنه.** درگاه پرداخت واقعی، دریافت کارمزد، امتیازدهی کاربران، بوم مدل
کسب‌وکار تعاملی، شبیه‌ساز قیف فروش، لجستیک، توصیه‌گر هوشمند و احراز هویت واقعی
کسب‌وکار.

## ۲. نقش‌های کاربری

| نقش | اختیارات |
| --- | --- |
| فروشنده | ثبت و مدیریت آگهی، توقف/فعال‌سازی آگهی، بررسی درخواست‌ها، ثبت پیشنهاد قیمت یا رد با دلیل |
| خریدار | جستجو و فیلتر، ثبت درخواست خرید، تأیید یا انصراف، پرداخت شبیه‌سازی‌شده |
| مدیر سامانه | داوری آگهی‌ها، مشاهده وضعیت کل سامانه، پایش ناوردای موجودی |
| مهمان | مرور بازارگاه و مشاهده آگهی‌ها بدون امکان اقدام |

## ۳. داستان‌های کاربری

### سمت فروشنده
- **US-01.** به عنوان فروشنده می‌خواهم موجودی مازادم را با مشخصات فنی استاندارد ثبت کنم تا خریدار بدون تماس تلفنی بتواند آن را ارزیابی کند.
  _پذیرش:_ فیلدهای الزامی بر اساس دسته ساخته می‌شوند؛ ورودی نامعتبر با پیام مشخص روی همان فیلد رد می‌شود.
- **US-02.** به عنوان فروشنده می‌خواهم بتوانم بخشی از موجودی را بفروشم و باقی‌مانده را ردگیری کنم.
  _پذیرش:_ دفتر موجودی سه‌بخشی و حداقل سفارش مستقل از موجودی کل.
- **US-03.** به عنوان فروشنده می‌خواهم درخواست‌های خرید را با قیمت نهایی خودم پاسخ دهم.
  _پذیرش:_ پذیرش با قیمت و مقدار، یا رد با دلیل اجباری.
- **US-04.** به عنوان فروشنده می‌خواهم ببینم هر متر از موجودی مازادم در چه مرحله‌ای است.
  _پذیرش:_ داشبورد با تفکیک قابل عرضه، رزروشده و فروخته‌شده + دفتر تراکنش.

### سمت خریدار
- **US-05.** به عنوان خریدار می‌خواهم بر اساس مشخصات فنی فیلتر کنم تا گزینه‌های نامناسب را از ابتدا حذف کنم.
  _پذیرش:_ فیلتر دسته، قیمت، موجودی، درجه کیفی، استان، عرض و گراماژ با برچسب‌های قابل حذف.
- **US-06.** به عنوان خریدار می‌خواهم وضعیت کیفی و ایرادها را پیش از مذاکره بدانم.
  _پذیرش:_ درجه کیفی سه‌سطحی + توصیف اجباری ایراد برای درجه B و C + نشان «مستند ایراد» روی تصویر.
- **US-07.** به عنوان خریدار می‌خواهم مطمئن باشم مقدار توافق‌شده برای من می‌ماند.
  _پذیرش:_ رزرو سیستمی در لحظه ایجاد سفارش و رد تأیید در صورت کمبود موجودی.
- **US-08.** به عنوان خریدار می‌خواهم سابقه درخواست‌ها و سفارش‌هایم را پیگیری کنم.
  _پذیرش:_ صفحه درخواست‌ها و سفارش‌ها با تاریخچه گذار وضعیت.

### سمت مدیر سامانه
- **US-09.** به عنوان مدیر سامانه می‌خواهم پیش از انتشار عمومی، کیفیت داده آگهی را کنترل کنم.
  _پذیرش:_ صف داوری با تأیید یا رد مستدل.
- **US-10.** به عنوان مدیر سامانه می‌خواهم از سلامت یکپارچگی موجودی مطمئن شوم.
  _پذیرش:_ پنل پایش ناوردا روی همه آگهی‌ها.

## ۴. نیازمندی‌های کارکردی

| کد | نیازمندی |
| --- | --- |
| FR-01 | فیلدهای الزامی فرم ثبت آگهی بر اساس دسته انتخابی تعیین می‌شوند. |
| FR-02 | موجودی کل، حداقل سفارش و قیمت واحد باید اعدادی بزرگ‌تر از صفر باشند. |
| FR-03 | حداقل سفارش نمی‌تواند از موجودی کل بیشتر باشد. |
| FR-04 | آگهی با درجه کیفی B یا C بدون توصیف ایراد ثبت نمی‌شود. |
| FR-05 | مقادیر فنی باید در بازه صنعتی باشند (عرض ۲۰–۴۰۰، گراماژ ۲۰–۱۲۰۰، سایش ۱۰۰۰–۲۰۰٬۰۰۰). |
| FR-06 | هر آگهی باید حداقل یک تصویر داشته باشد. |
| FR-07 | آگهی پیش از نمایش عمومی باید توسط مدیر سامانه تأیید شود. |
| FR-08 | رد آگهی یا رد درخواست بدون ذکر دلیل مجاز نیست. |
| FR-09 | مقدار درخواست خرید باید بین حداقل سفارش و موجودی قابل عرضه باشد. |
| FR-10 | فروشنده نمی‌تواند روی آگهی خودش درخواست خرید ثبت کند. |
| FR-11 | هر خریدار روی هر آگهی تنها یک درخواست باز می‌تواند داشته باشد. |
| FR-12 | ایجاد سفارش، مقدار را از «قابل عرضه» به «رزروشده» منتقل می‌کند. |
| FR-13 | پرداخت موفق، رزرو را به «فروخته‌شده» منتقل می‌کند. |
| FR-14 | پرداخت ناموفق یا انصراف، رزرو را آزاد و به «قابل عرضه» بازمی‌گرداند. |
| FR-15 | ناوردای «کل = قابل عرضه + رزرو + فروخته‌شده» در همه مسیرها حفظ می‌شود. |
| FR-16 | گذارهای غیرمجاز وضعیت (مثل پرداخت دوباره) رد می‌شوند. |
| FR-17 | هر تغییر موجودی یک رکورد حسابرسی با عکس لحظه‌ای دفتر ثبت می‌کند. |
| FR-18 | ثبت مصاحبه اعتبارسنجی، وضعیت فرضیه‌ها را بازمحاسبه می‌کند. |
