۲. ناوردای یکپارچگی موجودی

totalQuantity = availableQuantity + reservedQuantity + soldQuantity
availableQuantity ≥ 0 ,  reservedQuantity ≥ 0 ,  soldQuantity ≥ 0

تنها سه عملیات مجاز روی دفتر موجودی وجود دارد (src/lib/domain/inventory.ts):

عملیات انتقال محرک
reserve قابل عرضه → رزروشده ایجاد سفارش پس از تأیید خریدار
release رزروشده → قابل عرضه پرداخت ناموفق یا انصراف
commit رزروشده → فروخته‌شده پرداخت موفق

هر عملیات پیش از اعمال، کفایت مقدار را بررسی می‌کند و پس از اعمال، ناوردا را دوباره می‌سنجد؛ در صورت نقض، تغییر برگشت داده می‌شود و خطای تجاری برمی‌گردد.

۳. ماشین وضعیت آگهی

draft ──► pending ──► active ──► paused ──► active
                 │        │
                 │        ├──► sold_out ──► paused
                 │        └──► rejected
                 └──► rejected ──► pending

گذار active → sold_out به صورت خودکار و بر پایه دفتر موجودی محاسبه می‌شود (تابع deriveListingStatus): وقتی قابل عرضه و رزرو صفر شوند و فروش رخ داده باشد.

۴. ماشین وضعیت درخواست خرید

pending ──► awaiting_buyer ──► converted
   │  │              │
   │  │              └──► withdrawn
   │  ├──► rejected (با دلیل اجباری)
   │  └──► withdrawn

نکته: هیچ گذاری از rejected، converted یا withdrawn به بیرون وجود ندارد؛ این وضعیت‌ها پایانی‌اند.

۵. ماشین وضعیت سفارش

awaiting_payment ──► paid              (رزرو → فروخته‌شده)
        │
        ├──► payment_failed            (رزرو → قابل عرضه)
        └──► cancelled                 (رزرو → قابل عرضه)

هر سه وضعیت پایانی‌اند؛ تلاش برای پرداخت دوباره رد می‌شود.

۶. انواع تراکنش موجودی

نوع معنا مرجع
initial ثبت موجودی اولیه هنگام ایجاد آگهی listing
reserve رزرو مقدار برای یک سفارش order
release آزادسازی رزرو order
commit قطعی‌سازی فروش order
adjust اصلاح دستی موجودی (در فاز ۱ استفاده نشده) listing

هر رکورد یک snapshot از وضعیت دفتر پس از همان تراکنش نگه می‌دارد؛ بنابراین ناوردا در هر نقطه از تاریخ قابل بازرسی است.
